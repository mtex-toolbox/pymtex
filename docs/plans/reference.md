# The function reference

A reader of mtex-toolbox.github.io who follows a function link lands on MATLAB's reference page
(`fibre.angle.html`), whose calling forms do not carry over to Python (issue #4). This subplan
writes the Python twin of every reference page from the docstrings, on the scheme of the
documentation pages (D5 of `docs.md`): a sibling `<name>_py.html`, listed in
`_data/python_pages.yml`, so the site's MATLAB | Python switch (`js/mx-lang.js`, which matches
any `<name>(_py)?.html`, dotted names included) takes the reader to it with no change on the
site's side.

## 1. What there is (2026-10-14)

- MATLAB's reference: 2524 pages in `../web/pages/function_reference_matlab/`, one per
  `<class>.<method>` or function, generated by MATLAB's publish: summary, Syntax, Input,
  Output, See also, an edit link to the source.
- Python's public surface, the flat `mtex` namespace: 206 classes, 563 functions, 1765 members
  (495 of them properties). Docstrings: 167 empty, 1305 one line, 411 two, 445 three or more;
  126 show calling forms as indented lines, 177 cite `MATLAB's <name>`.
- The counterparts: the graph (`tools/graph/out/graph.json`) has 3793 Python-MATLAB
  `counterpart` edges; 1482 of the 2524 MATLAB pages have a Python node behind them, 637 of
  them through a function serving several classes (`smooth` behind `EBSD.smooth`,
  `grain2d.smooth`, ...). The other 1042 are functions the port has not, or under another name
  the graph does not link.

## 2. The steps

**R1 - the generator.** Built 2026-10-14: 3044 pages, 1538 under MATLAB's names (439 of the
462 reference links of the doc pages), 1506 Python-only; seven seconds; `tests/test_reference.py`.
The pairing resolves a MATLAB name at run time, what `EBSD.fill` reaches on the Python class (an
alias table for the MATLAB classes folded into one, `Miller` into `vector3d`, the renames of
`syntax.md`, a method MATLAB has on the class found as a function of the flat namespace), not the
graph's counterpart edges, which match by name across the port. "Used on" lists a method only
where no other class has a member of its name. `docs/reference.py` imports `mtex`, walks the public namespace as
`tools/staticapi.py` does, and writes `docs/build/reference/<name>.md` per public function,
class and member:

- the name and the one-line summary, the signature from `inspect.signature` (annotations
  shortened: the `Literal` vocabularies as "a point group name", not the list);
- the rest of the docstring, prose as paragraphs, indented lines as a Python code block;
  names in backticks that are public become links to their pages;
- the counterpart: "MATLAB's `fibre.angle`" with its link, from the graph's edges (the
  `MATLAB's <name>` citations of `syntax.md` included);
- the doc pages that call it, read off `docs/pages/**/*.py` (the graph's call edges from the
  pages), as MATLAB's pages have none and they are the best examples there are;
- for a class: its constructors, properties and methods as a table of summaries; for a
  member: its class and the inherited members it overrides;
- the source link, `blob/main/<file>#L<line>`.

The page name is the MATLAB page's where a counterpart exists, so the switch pairs them; a
function behind several MATLAB pages writes each of them. A Python-only name (`ucvHalfwidth`) takes `<class>.<name>` or `<name>` as MATLAB would
name it. Tested by `tests/test_reference.py`: every public name has a page, every link in a
page resolves, the issue's `fibre.angle` page shows `return_nearest`.

**R2 - the index and the export.** Built 2026-10-14: `FunctionReference`, MATLAB's index page
name, lists every class and function by layer; `docs/site.py ../web` exports the reference with
the documentation pages (3045 pages), a Python-only name that a documentation page has already
taken as `mtex.<name>` (`mtex.SchmidFactor`). A Jekyll build of a copy of the site (seven
minutes, the gems outside the site, whose `exclude` replaces Jekyll's default) rendered them
with every link resolved. Only the 1538 pages with a MATLAB twin enter `python_pages.yml`. The site's
switch (`../web` 2026-10-14) no longer inlines that list into every page, 38 KB of a reference
page's 59 KB: a page carries `<meta name="mx-python">` when it has a twin, written at build time,
and `js/mx-lang.js` fetches `python_pages.json` once for the links; a link followed before the
list arrived opens MATLAB's page, which forwards. Checked in a headless browser on a built copy. `docs/reference.py` also writes the index pages by class
and by layer (geometry, functions, tensors, maps, maps3d, analysis, io, plotting), Python's
twin of `function_reference.md`. `docs/site.py` exports `docs/build/reference/` into
`pages/function_reference_python/` with front matter (`sidebar: function_reference_sidebar`,
`permalink: <name>_py.html`) and adds the names to `_data/python_pages.yml` with status
`Reference`. Checked by a Jekyll build of a copy of the site, then the preview
(`mtex-playground.github.io`, `tools/deploy-next.sh`), then live on the user's word.

**R3 - the docstrings.** Done 2026-10-14: every public name has a docstring (a test of
`tests/test_reference.py`; an operator shows its form, `a + b`), the 200 most called functions
show their calling forms (ranked by the calls of the doc pages, a name several classes share
split among them), `plot` lists every kind it draws and a class's plot page shows the function
`plot` hands it to (`PLOT` in `docs/reference.py`); `quaternion.mean` and `orientation.mean`
give the moments of inertia and the projected orientations, `vector3d.mean` the projected
directions, on request. The forms were written by three agents, each form run; what they found
not working is the list below. The plan as first written: A one-line docstring makes a thin page. Ranked by how often MATLAB's
tutorials and the Python pages call a function (the graph's call edges), the first 200 get
their calling forms as indented lines, MATLAB's Syntax block translated, each keyword the
function takes named in a sentence, as `fibre.angle` now has; the other optional outputs
(MATLAB's `nargout > 1`) are listed while doing so and each gets its `return_*` keyword or a
note why not. `tools/staticapi.py --check` reports public names with an empty docstring, so
the 167 do not grow back.

**R4 - in the editor and the package.** Built 2026-10-14: `docs/reference.py` writes
`mtex/io/referencenames.json`, the page of every Python name (a class, a function of the flat
namespace, `Class.member`; 2442 names), shipped with the package and kept current by a test;
`openDoc('fibre.angle')`, `openDoc(calcGrains)`, `openDoc(ori.mean)` open the reference page in
the browser, a documentation page's name keeps opening the page as a script. On the site
`docs/site.py` writes the table as `python_refs.json`, and `js/mx-reflinks.js` (loaded on the
pages with `lang: python`) links the names of the highlighted code after the page is drawn: a
function or class of mtex, `Class.member`; not a method called on a variable, whose class the
code does not say, a keyword argument or an assigned name. The plan as first written: `help()` and hover already read the docstrings; the
pages add a "Reference" link per function in the doc build (`docs/make.py` links the names in
a page's code to their reference pages), and `openDoc('fibre.angle')` opens the page in the
browser.

## 3. What the calling forms found (2026-10-14)

MATLAB forms that did not work in Python, fixed the same day by three agents, each with a test of
the general case: the flat `cat` of every class with a `cat`; `max`/`min` of S1 functions with a
number, a function or `numLocal`; `angle(sVF, v)`; `calcError(odf, pf)` in MATLAB's order;
`axis(o1, o2)` across crystal frames and `axis(mori, cs)`; `variants(p2c, ori)` as parents x
variants; `inpolygon(grains, rect | poly)` by the centroids, MATLAB's meaning (the points' grains
are `grains[x, y]`); `strainTensor(M, type=)`; NumPy's reductions of tensors; `tensor.rand`
uniform; `round(m, return_error=True, maxXYZ=)`; `f.rotation(return_angles=True)`;
`vector3d.rand(n, sR)`; the zone law strings `Miller('[uvw]\\[uvw]', cs)`; `sum(odf, d)`;
`S2Fun.smiley(even=True)` antipodal; and the named fibres alpha and tau, wrong in MATLAB too and fixed on develop
(`docs/plans/develop-fixes.md`). Kept: `calcError`'s defaults, which are MATLAB's code if not
its documentation; `abs(sF, bandwidth=)` of `S2FunTri`, which MATLAB's signature does not take.
Done after: `cat` of grains and boundaries (parts of one segmentation, a grain or segment in two
parts kept once), NumPy's reductions of every container, MATLAB's `accuracy` of `round`. Left:
`strainTensor`'s ellipsoid, the only user of its type.

### Found while writing the sections of the other 535 and rewriting the long descriptions (2026-10-14)

Every public function or method taking a keyword has MATLAB's sections (six agents, 968 pages

`calcTensor`, `interpolate`, `SchmidFactor`, `PoissonRatio`, `calcComponents`, `calcCluster`,

### Help quality review (2026-10-15)

The follow-up review inventories 2,409 distinct documented objects and locates MATLAB
counterparts in `../master` for 1,823 of them. It expands 427 help entries, including the
117 flat-namespace method forwarders. Existing complete descriptions and straightforward
property definitions stay concise. MATLAB help supplies context and examples; Python source
determines the accepted arguments, units, return values and differences in behaviour.

The additions cover constructors, coordinate and symmetry operations, kernels and harmonic
functions, maps and boundaries, tensor mechanics, spatial transforms and colour keys.
`crystalShape` now explains plane distances, habitus, extension, scaling, selection and its
properties, with a self-contained plotting example. Corrections include `mPrime`'s single
return value, affine decomposition angles in degrees, Bingham's single-orientation input,
and valid Python syntax in the calling forms.

The generator renders `Properties` tables and each class constant's own help, and writes
NumPy type defaults as Python expressions. The reference and static API checks cover all
published names, links, keyword tables and calling-form syntax. Focused domain checks pass
(303 tests); representative numerical examples confirm the documented outputs and
normalisation. The full reference exports 3,015 pages for the website preview.
The Jekyll preview builds successfully, and 18 representative pages render at desktop
and phone widths. Literal arithmetic is formatted as code so Markdown preserves its
operators. A small change to `../web/css/mtex-site.css` wraps long citation URLs and
reference-table text while keeping argument names intact. The complete reference
export and the stylesheet are published together, with the
reference-name map and the MATLAB/Python counterpart table kept in sync.

## 5. Worked examples (2026-10-15)

A review of the 3,014 generated function reference pages and the calls in 238 Python tutorial pages found one executable `Example` section: `crystalShape.plotSlipSystem`. Other pages contain calling forms and some already include substantial setup in Syntax or Description. The priorities below account for that existing content as well as tutorial usage.

The usage count is the number of distinct tutorial pages containing a direct call to the stated Python name, parsed from Python syntax. Calls through instance variables are excluded because the receiver type is not determined. Counts measure dependency and exposure, rather than website traffic. `crystalShape` has a complete prism setup in Description, so its next improvement is to execute and illustrate that code. `selectHalfwidth` is less frequent in the current tutorials, but it deserves an example because grouping, angular units and its relationship to `calcDensity` are difficult to infer from isolated calling forms. `EBSD.load` appears directly on seven tutorial pages; include it with the sample-data example, while keeping file-format corrections specific to the demonstrated file.

Each new example should define its imports, frames, data and units; use deterministic small inputs; and include the actual printed or graphical output. Prefer synthetic inputs where they explain the operation. An EBSD or pole-figure workflow may use sample data when that is what the function operates on, with the download and expected runtime stated. Keep the executable code in the source docstring so the published result can be regenerated by `docs/reference.py`.
